# 无人值守部署与恢复实施规格

日期：2026-10-24。依据：用户要求持续无人值守推进，现有最终交付目标为用户服务器部署与线上验收。对应 #17，推进 #14 中不依赖服务器连接的部分；不替用户选择公网主机或声称临时环境已上线。

## 工程选择及职责

以下为本轮工程实施选择，非用户逐项确认的新需求。新增“部署与运行保障”模块：`operations.py` 提供私密配置预检、SQLite 一致性备份、备份验证及恢复；`部署/` 提供独立生产 Compose、Caddy 配置与运维入口；测试和 Actions 验证真实 HTTPS、会话与状态恢复。游戏裁定、模型权限及 mist-v1 规则不变。

- 生产入口使用 Caddy 自动申请 HTTPS；只有反代暴露 80/443，应用不发布宿主机端口。专用 Docker 网络仅含应用与反代，应用只信任反代的固定私网地址；子网和地址可以配置，以避免与目标服务器网络冲突。
- Caddy 只接收站点地址，不接收 DeepSeek 密钥或入镇口令。应用配置由私密 `.env` 注入，生产固定 Secure Cookie。内网服务名追加至 NO_PROXY，保留环境原有代理设置。云环境构建/运行使用只读 CA 挂载，不把会话 CA 或密钥写入镜像。
- 配置预检检查密钥已配置、入镇口令长度、HTTPS 站点地址语法、Secure Cookie、AI 轮数。只输出字段名和状态，不输出任何配置值；不借预检扫描或选择远程服务器。localhost 仅在显式本机验收模式使用。
- 在线备份使用 SQLite backup API 获取事务一致快照，保留对局、回执、审计和会话摘要。校验完整性和已知规则/schema 后，以原子且拒绝覆盖的方式交付新文件，权限 0600，输出校验和及数量，不输出身份、对白或会话摘要。
- 恢复同样拒绝覆盖既有数据库及残留 WAL/SHM/journal；不提供强制覆盖开关。管理员停服、保留旧库，再恢复到新目标并启动，避免在线替换正在使用的 inode。未知规则或损坏文件拒绝恢复。

## 验收

1. 配置缺项、非法站点、弱口令时失败且不泄露值；正常预检不请求模型。
2. 有真实会话和私聊的数据库备份、重启、恢复后，同一 cookie 可恢复同一对局与私有记录；重复请求回执仍有效。公开接口不能取得他人私有信息。
3. 备份过程中并发事务写入，快照仍通过完整性校验；已有目标、同路径、损坏库、未知规则及陈旧 sidecar 被拒绝，不破坏原文件。
4. 实际 Caddy + 应用经 HTTPS 访问，使用测试 CA 显式验证证书，不关闭 TLS 校验。Secure/HttpOnly/SameSite Cookie、HTTPS 同源写入、普通身份隔离、容器重启/恢复通过。Caddy 配置经真实二进制验证。
5. CI 使用离线模型或无调用的测试配置；真实 DeepSeek 经当前云端服务单独作有限验证。日志、截图及发布资料不得含真实密钥或会话 cookie。
