## 交付边界

先交付“游戏对局”业务中“回合与规则裁定”和“对局记录”的底层内核，提供进程内 Python 接口与命令行演练。模式固定标记为 `kernel_rehearsal`，不是完整预女猎白剧本；没有网页、AI 模型调用或部署入口。

内核可创建标准十二张身份牌，固定一名真人、十一名 AI 标识，真人可选身份或随机。身份不关联人格，后续人格模块不能改变权限。正常发牌使用系统随机源；受信测试可注入固定随机源。

演练只串联“狼队夜袭投票 → 狼队内部计票 → 依座位公开发言 → 下一轮夜袭投票”。白天按座位发言仅为内核演练的确定顺序，不是对完整剧本发言顺序的定案。计票结果记录的是袭击选择，**不会直接使目标死亡**；不能跳过女巫等阶段后把这个结果当作实际夜间死亡。完整剧本驱动器须在后续任务替换演练调度。

## 信任和恢复

`GameService`、`bind_player`、主持快照和 SQLite 文件属于受信应用层。`PlayerSession` 只是已绑定操作者的进程内能力包装，**不构成公网鉴权系统**；未来 HTTP 层必须先认证并确定所属对局与座位，不能把主持对象、自由绑定接口或数据库交给玩家。模型只接收视图和已绑定的行动工具，不执行任意 Python。

事件保存对局、轮次、窗口、操作者、时间和可见对象。玩家读取先过滤记录，再输出副本，不能读取其他人的身份事件、请求缓存或拒绝审计。原始工具记录属于内部验收接口，后续网页与剧本文案层须转换为世界内语言，不能直接展示这些结构。当前不承诺隐藏流量、全局版本或事件编号等元数据。

文件数据库可由新服务实例重新打开，恢复阶段、身份、请求去重结果与事件。`BEGIN IMMEDIATE` 串行化相同文件上的写事务，避免并发重复生效。当前以单机内核验证为目标；快照包含完整历史，不声称已实现生产级事件溯源、跨机扩展、数据库加密或灾备。

## 验收与后续裁定

以下保留待定或后续实现：完整夜间技能顺序、警长选举与双爆、猎人/白痴临界结算、死亡与胜负、遗言及死亡后可见性、工具记录玩家展示、LangGraph 持久化与模型选择、RAG、网页与 Phaser、部署。预言家连续查验限制等规则仍不能从调研稿自动提升为用户决定。Issue #1 只完成本内核所需范围核对，继续保持开放；Issue #6 只完成 Python 部分，前端构建尚待 Issue #5。
