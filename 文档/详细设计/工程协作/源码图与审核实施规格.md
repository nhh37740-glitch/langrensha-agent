# 源码图与 CLI 审核实施规格

依据：用户本轮“继续，然后再看一看新的 issue”，以及仓库所有者提交的 #20、#22。按无人值守授权实施，不改变游戏裁定和权限。工程版本 v0.4.1；#21 的界面改版独立实施。

## Copilot 优先

新增可复用 CLI 脚本，在 PR 创建或更新后先请求 `@copilot`，旧版 gh 请求失败时使用同一 GitHub API 的 reviewer 入口。记录请求方式、当前 head、审查状态、review/comment 链接；不保存令牌、应用密钥或完整 provider 响应。只接受当前提交的有效 Copilot review，额度不足留言、旧提交、待审请求不能算审查通过。默认每 30 秒查询，最多 10 分钟；网络/权限失败、明确不可用或超时后输出可记录的降级原因，不自动启动第二种付费审查。需要降级时再明确记录并请求 Codex，之后仍检查所有意见、线程和 Actions。推送新提交须重新核对。

同步 AGENTS、Copilot/项目开发 agent 指引、PR 模板及开发规范；以 #22 的最新降级策略取代旧 PR #8 中“Copilot 不可用时无限等待”的提议，不将未合并提议当作主线规则。GitHub 设置若配置自动 Codex 审查，脚本不能关闭它，不假称减少了该设置产生的调用。

## 代码架构

用仓库内 Archify Skill 生成独立源码架构视图，沿真实调用追踪浏览器、HTTP/认证、受限会话、服务事务、领域裁定、呈现、检索、AI/札记、外部 provider 和 SQLite。图源引用已提交的完整 SHA，源码证据长期保存在对应 evidence 分支。关系证据归属实际调用者，配五分钟讲解及调用证据表，不能把模型直接连到事实库。保留已有部署及发布图。版本图检查发现并重建新图，发布前核对版本图存在且固定提交可追溯。

## 验收

CLI 替身测试覆盖旧提交、额度失败、有效 review 和不可用，实际 PR 发起 Copilot 请求并记录真实结果。五项 Actions 保持要求；架构图源码/产物及浏览器检查通过，附面试主链和 AI 分流的源码证据。合并并通过主线检查后才创建 v0.4.1 标签和 Release。

## 架构约束补充（#23）

新 Issue #23 明确授权自主调研、选择和实施。选择现有模块化单体 + 向下依赖/同层独立契约，使用 BSD-2-Clause 的 Import Linter 2.15，仅加入 dev 依赖；锁定其新传递依赖。层级穷尽检查要求新增模块先归属层；纯规则/查询/呈现不依赖 Web 或模型框架，模型不可导入主持/存储，Store 只由服务装配。CI Python 原检查中强制执行，新增四项真实工具负例验证，不改业务行为。Phaser 渲染层通过 ESLint 禁止直接网络全局和反向导入页面入口。取舍、覆盖范围与剩余耦合记录在正式架构评估中。
