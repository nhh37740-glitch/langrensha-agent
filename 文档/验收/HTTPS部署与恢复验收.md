# HTTPS 部署与恢复验收

日期：2026-10-24。对应 #17，推进 #14 的部署准备。正式服务器身份仍未取得，以下均为当前云环境的本机容器验收，不声明已在用户服务器上线。

## 自动与实际容器验证

- 全量 Python 155 项通过，包括新配置、并发一致性备份、拒绝覆盖、损坏/未知版本拒绝、会话与幂等回执恢复、脱敏审计统计；Ruff 和 Bash 语法检查通过。
- Caddy 2.11.7 与应用容器实际运行，使用 localhost 测试 CA 显式验证 TLS，不关闭证书校验。
- HTTP 跳转 HTTPS、Secure/HttpOnly/SameSite Cookie、HTTPS 同源写入、伪造转发头和跨源请求拒绝通过。
- 两个会话随数据库快照恢复；快照后的新记录不混入恢复库；旧请求重试仍保持原回执和状态版本；普通身份不能取回其他对局的私密历史。
- 运行中再次启动独立 ops 容器预检、验证和恢复成功，避免固定应用 IP 与一次性运维容器冲突。Docker 网络设置不改变宿主或平台代理路由。
- 仅向 CI 上传结果 JSON；私密配置、原始数据库、浏览器 cookie 和证书私钥不上传。

## 真实模型验证

第一轮 HTTPS 完整实战实际产生第 6 日夜裔胜利，但验收脚本最终审计断言失败；该轮不记为完整验收通过。随后改为先保留分类审计与私密数据库，再核对窗口数量及原生工具生效；模型临时不可用按既定规则弃权，不要求外部服务永不出错。连续不可用会使测试提前结束，避免无意义请求。

带审计的真实 HTTPS 完整局正在重验，结果另行追加；未完成前不作通过声明。真实模式明确启用 API 费用，普通 CI 使用无模型调用的配置。
