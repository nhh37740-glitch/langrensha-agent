## 分层速览

| 层 | 源码 | 职责 |
| --- | --- | --- |
| 页面与渲染 | `前端/src/main.js`、`前端/src/scene.js` | 同源 API 请求；把受限状态交给 DOM 与 Phaser，不自行裁定 |
| HTTP 入口与认证 | `src/langrensha/web.py` | 同源头/口令/摘要校验、会话表、逐窗口推进与静态网页 |
| 应用服务与受限会话 | `src/langrensha/service.py` | `GameService` 事务编排；`PlayerSession` 固定已认证操作者 |
| 领域规则 | `src/langrensha/full_game.py`、`src/langrensha/rules.py` | 纯状态机裁定；身份、席位、事件等基础（无数据库 I/O） |
| 查询与呈现 | `src/langrensha/presentation.py`、`src/langrensha/retrieval.py` | 受限视图转网页数据；只在已过滤视图内检索 |
| AI 编排 | `src/langrensha/ai.py`、`src/langrensha/assistant.py` | LangGraph 有界决策；札记只整理已检索资料 |
| 持久化 | `src/langrensha/store.py`、SQLite 文件 | 事务快照、幂等回执、拒绝与决策审计、会话摘要 |

## 第一分钟：入口和会话

`main.js` 发送同源 API 请求，并把服务器返回的受限状态交给 DOM 与 `scene.js`。`web.py` 验证同源头、口令和 cookie 摘要，从服务器会话表取得固定席位，调用 `GameService.bind_player` 创建 `PlayerSession`。客户端没有 actor 选择接口；模型也拿不到 GameService。

## 第二分钟：一次行动如何落地

真人提交 `request_id`、`phase_id`、`expected_version`、工具与参数。`PlayerSession.submit` 补入已绑定的操作者，进入 `GameService._submit`。服务在 `Store.transaction()` 中加载快照、调用纯 reducer、保存新快照。拒绝会写拒绝审计，不增加对局版本；事务使用 `BEGIN IMMEDIATE`。`full_game.reduce_action` 验证请求回执、阶段、版本、授权工具和目标，复制状态后才施加行动。模型说“我投票了”不构成行动。

## 第三分钟：查询为何不泄密

`full_game.player_view` 先按事件受众、死亡时间和身份过滤；`GameService._view` 从这里取得视图。`PlayerSession.query` 只把这个视图传给 `retrieval.query`，没有把主持快照交给检索后再删结果。网页使用 `presentation.present` 将已经过滤的视图变成叙事、身份显示和操作选项；呈现层不能代替授权层。

## 第四分钟：AI 与札记是两条路径

HTTP `/advance` 仅在待行者不是当前真人且对局未结束时，为该 AI 绑定独立 PlayerSession 后运行 `DecisionRunner`。LangGraph 的 model → dispatch 循环有轮数上限；查询走 `session.query`，行动走与真人相同的 `session.submit`。外部 DeepSeek 接收受限上下文和当下工具，不能直接修改 SQLite。耗尽/模型故障走受控弃权，决策报告由服务写主持审计。

真人札记走 `safe_query`：先检索，再可选调用 `assistant.assist`。这个模型只得到可见来源和 `compose_note`，引用必须来自已给定来源；它没有对局行动工具，结果也不会自动发表。失败保留原文整理。

## 第五分钟：存储和设计取舍

Store 负责文件 SQLite 的事务、JSON 快照读写。完整状态内含事件和幂等回执，另外有拒绝审计、AI 决策表及 web 会话摘要。它是“事务快照 + 事件记录”，并非完整事件溯源。`rules.py` 复用 Role、席位校验、事件等基础，并保留历史演练；完整局的 reducer 在 `full_game.py`，服务按 mode 分流。单 worker 是当前部署约束，不声称已实现分布式调度。
