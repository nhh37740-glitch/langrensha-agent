# 完整可玩版运行与部署

版本 v0.3.0，规则 `mist-v1`。当前完整源码、生产网页及发行包可构建；是否已合并、构建和验收以对应 PR/Actions、[验收记录](../验收/完整可玩版验收.md)为准。没有用户服务器入口及凭据，不声明已在用户服务器上线。

## 本机启动

需要 Python 3.12+、Node.js 24。仓库目录执行：

```bash
python -m venv .venv
.venv/bin/python -m pip install -c requirements-dev.lock -e '.[dev,ai,web]'
npm ci --prefix 前端
npm run build --prefix 前端
cp .env.example .env
chmod 600 .env
# 编辑 .env：填入自己的 DEEPSEEK_API_KEY；不要把密钥写进命令、截图或 Git。
.venv/bin/langrensha-web
```

打开 http://127.0.0.1:8000 。默认本机监听，未设访问口令时入镇口令留空。选择或随机身份，正文显示证词，行动栏只给当前合法选择。札记可查背景、自己使命、指定玩家陈述、历史及可编辑发言建议，并展开查看出处。指定玩家总结、背景回答和发言草稿会把已经过滤的资料交给 DeepSeek 整理；只允许返回有来源的札记，不能发言或用技能。模型不可用或返回未知来源时退回原文摘录。秘密身份采用镇中称呼：夜裔/镇民/观星者/药师/守林人/守誓者。

每个请求最多推进一个 AI 行动窗口；浏览器自动推进到真人操作处，无游戏倒计时。暂停旅人会停止下一次推进；正在处理的一次请求可能完成，刷新由持久化状态恢复，不重复已提交的技能。关闭页面后不再请求新窗口。API 未接通会停下并显示提示，已接受的状态不丢失。思考轮数由服务器 AI_MAX_ROUNDS（1～20）控制；失败或轮数用尽同阶段弃权，真实原因只在主持审计。

旧 `langrensha-demo` / `langrensha-ai-demo` 是历史版本演练；完整游戏入口是 `langrensha-web`。

## 自动验收和发行包

```bash
.venv/bin/python -m ruff check src tests .github/scripts
.venv/bin/python -m pytest
npm run lint --prefix 前端
npm run build --prefix 前端
cd 前端
npx playwright install --with-deps chromium
npm test
cd ..
.venv/bin/python -m langrensha.full_demo
# 显式计费真实验收，真人由仅弃权的测试替身代替：
.venv/bin/python -m langrensha.full_demo --real --limit 350
.venv/bin/python -m build
```

真实验收把 SQLite、进度与不含密钥/私有对白的结果放到指定的 `临时/` 子目录。无网络验收的策略使用主持事实构造确定性胜利，不能把它描述成 AI 推理成功。CI 不读取任何 DeepSeek 密钥，仅用工具协议替身验证控制流；真实模型结果另记。

先构建网页再 `python -m build`，wheel 自带 `static/index.html` 和本地 Phaser/样式包，不依赖第三方 CDN。GitHub Actions 的“前端与发行包检查”保存 wheel、sdist、浏览器截图及失败 trace，可直接下载 wheel 并安装 `[ai,web]`。Python 单独检查的包只验内核，完整网页发行包以此前端工作流产物为准。

## 用户服务器部署

需要服务器 SSH 入口、可部署账号及 HTTPS 域名；本仓库没有这些信息。请在取得目标后记录具体版本、入口和线上验收。服务器需要 Docker/Compose、HTTPS 反向代理及到 api.deepseek.com 的 HTTPS 出站访问。

1. 克隆仓库并检出已合并的发布 tag；将 `.env.example` 复制为 `.env`，填入 DeepSeek 密钥、随机高熵 `LANGRENSHA_ACCESS_TOKEN`，HTTPS 环境设 `COOKIE_SECURE=true`，文件权限 0600。
2. `docker compose up -d --build`。容器以非 root 用户运行，只映射服务器回环 8000 端口，SQLite 与会话摘要保存在 `town-data` 持久卷。密钥不进入镜像、前端、仓库或 Actions。
3. HTTPS 反向代理转发到 `127.0.0.1:8000`，保留原始 Host，传递 X-Forwarded-Proto。Uvicorn 默认只信任回环代理；容器桥接代理应通过受控网络配置受信代理地址，不要公开接受任意客户端转发头。若代理位于宿主机，优先让其连接本机回环映射并显式配置 Uvicorn 的受信代理地址。HTTP 本地验证需临时设 COOKIE_SECURE=false；上线恢复 true。
4. `curl --fail http://127.0.0.1:8000/api/health` 核对版本；打开 HTTPS 入口，入镇并完成一局，刷新重连后核对记录，检查普通身份不能读其他人的私密内容。

服务仅使用单 worker。当前串行锁与单文件 SQLite 面向个人完整局，多个会话共享 AI 推进锁；不要用多个 worker 或多个容器同时操作同一数据库，除非另做分布式任务租约。此项是部署约束，不是已完成的多租户横向扩容。

备份：停止服务后复制持久卷数据库，或使用 SQLite 在线 backup API；数据库含私有对局记录，应按服务器私密资料保管。恢复时停止服务、还原同规则版本数据库、启动并用原浏览器会话恢复。升级前保留旧 tag、镜像与数据库备份；不对旧数据库直接进行未经测试的结构迁移。

更新和回退都先停服务，再切换目标 tag 重建；完整版本同时保留旧内核演练快照，不冒充其为完整游戏。远程监听缺少入镇口令时启动会拒绝。
