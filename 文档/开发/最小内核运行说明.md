# 最小内核运行说明

本版本对应 Issue #2。它提供十二人发牌、狼队计票、公开发言、记录与权限的底层演练，不是可供真人游玩的完整剧本。具体边界见[实施范围](../详细设计/首个可玩版本/最小内核实施范围.md)。

## 初始化与验证

从仓库根目录使用 Python 3.12 或更新版本：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -c requirements-dev.lock -e '.[dev,ai]'
.venv/bin/python -m ruff check src tests .github/scripts
.venv/bin/python -m pytest
.venv/bin/python -m build
.venv/bin/python -m langrensha
```

最后一条命令创建并清理临时数据库，完成夜袭投票、十二人发言、进入第二轮夜晚，输出普通玩家无法读取狼队计票的结果。没有调用模型，不需要 API Key，也不启动网络服务。`临时/内核演练/` 为运行产物目录，已被 Git 忽略。

## 受信应用层调用

```python
from langrensha import GameService

service = GameService('临时/本次对局/game.sqlite3')  # 父目录须先创建
game_id = service.create(human_seat=1, human_role='wolf')
player = service.bind_player(game_id, 1)  # 只能由受信应用层绑定
view = player.view()
receipt = player.submit({
    'request_id': '本次请求的唯一编号',
    'phase_id': view['phase_id'],
    'expected_version': view['version'],
    'tool': 'wolf_vote',
    'payload': {'target': 3},
})
```

可用工具以 `view['tools']` 为准。夜晚仅狼人可私聊、投票或弃权；白天演练按座位发言或沉默。不要读取主持快照后直接把完整状态发送给玩家或模型。

相同请求必须原样重试，包括原来的窗口、版本及参数，服务返回原回执。若不同请求因 `stale_version` 拒绝，先重新获取视图，确认仍有行动资格后使用新请求编号。`stale_phase` 表示原阶段已经结束，不能重做该次选择。`tool_not_allowed`、`invalid_payload` 等拒绝不会修改对局状态；仅主持审计记录拒绝原因。

SQLite 文件含私密身份与事件，应由服务进程独占管理。重新打开同一文件、使用原 `game_id` 可继续处理；演练命令退出会清理自己的文件，如需保留应通过上述库接口创建。
