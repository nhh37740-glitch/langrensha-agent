后端究竟怎样运行

它是一个 Python 网络程序：收到行动，读出一局字典，执行条件分支，保存字典，再返回玩家能看的内容。AI 的额外工作是请求模型，把回复转成同样的行动输入。

这里按函数实际执行顺序拆成六张图。先读 01→02→03→04，再看 AI 和检索两条支线。图内节点保留源码原名，点击节点可定位源码；返回本页用浏览器后退。图和文字均可离线打开，GitHub 源码链接需要联网。

先把文件和数据对上

启动命令 langrensha-web 指向 web.main()：创建模型、调用 create_app() 注册 FastAPI 接口，然后 uvicorn.run(..., workers=1)。这里没有“每个模块一个服务进程”。网页只是 HTTP 调用者。

源码里的名称在这个程序里具体是什么
GameService / StoreGameService 持有一个 Store，把读取、规则计算、保存放进事务。Store 打开 SQLite 连接，执行 SQL 和 JSON 编解码。
PlayerSession一个保存服务对象、局号和席位的 Python 对象。submit/view/query 使用这些固定值；它不是 Cookie，也不是数据库连接。
state / view都是字典。state 是完整对局；player_view(state, actor) 生成这个席位可见的 view。AI 的 LoopState 是另一份循环数据，不能当作完整对局。
events / receiptsevents 是记录列表；receipts 是以“席位:请求编号”为键的字典。它们都嵌在整局 state 中，存成 games.state 的 JSON，不是两张独立 SQL 表。
task / queue / completed当前阶段描述字典 / 后续阶段字典列表 / 已完成选择的字典。它们是普通内存数据，没有线程池或消息中间件。

真实代码节选：service.py:132–147；省略部分请点源码。

class PlayerSession:
    """操作者由受信层绑定；submit 只接受窗口、版本、工具和参数。"""

    def __init__(self, service, game_id, actor):
        self._service, self._game_id, self._actor = service, game_id, actor

    def view(self):
        return self._service._view(self._game_id, self._actor)

    def query(self, name, payload):
        from .retrieval import query

        return query(self.view(), name, payload)

    def submit(self, command):
        return self._service._submit(self._game_id, self._actor, command)

这些是运行时结构节选，不是完整字段清单。下文投票实例来自真实 TestClient、SQLite 和规则函数；AI 回复用脚本替身，语义评分使用实际 ONNX 模型。UUID、时间会随运行改变。源码固定在 8a4a82a，不会随 main 的后来变动跳到别的实现。

02 · service.py / store.py：一次事务内做什么？

打开 Archify 流程图 ↗

PlayerSession.submit(command) 补上固定的 game_id、actor，调用 GameService._submit。Store.transaction() 创建 sqlite3.Connection，执行 BEGIN IMMEDIATE，把连接交给 with 内函数。load 用 SELECT 取文本并 json.loads；规则返回新字典与回执；save 用 json.dumps 后 UPDATE，建局时才 INSERT。

正常退出 with 才 commit。规则拒绝在 with 内被捕获，只 INSERT rejections，因此拒绝记录先提交，之后才向上 raise。其他未捕获异常由 transaction rollback，finally 关闭连接。成功后的 view 是另一事务读取，可能看见比本次回执更新的数据。

真实代码节选：store.py:40–53；省略部分请点源码。

    @staticmethod
    def load(db, game_id):
        row = db.execute("SELECT state FROM games WHERE id=?", (game_id,)).fetchone()
        if row is None:
            raise KeyError("game_not_found")
        return json.loads(row[0])

    @staticmethod
    def save(db, state, *, create=False):
        encoded = json.dumps(state, ensure_ascii=False, sort_keys=True)
        if create:
            db.execute("INSERT INTO games(id,state) VALUES (?,?)", (state["id"], encoded))
        else:
            db.execute("UPDATE games SET state=? WHERE id=?", (encoded, state["id"]))

真实代码节选：service.py:112–129；省略部分请点源码。

    def _submit(self, game_id, actor, command):
        error = None
        with self.store.transaction() as db:
            state = self.store.load(db, game_id)
            try:
                updated, result = reduce_action(state, actor, command, now=utc_now())
            except Rejected as exc:
                error = exc
                db.execute(
                    "INSERT INTO rejections(game_id,actor,code,time) VALUES (?,?,?,?)",
                    (game_id, actor, exc.code, utc_now()),
                )
            else:
                self.store.save(db, updated)
        # 拒绝审计先提交，再抛异常；不修改对局快照或递增版本。
        if error is not None:
            raise error
        return result

03 · full_game.py：怎样接受、拒绝与防止重复？

打开 Archify 流程图 ↗

service.reduce_action 按 mode 选规则；完整局进入 full_game.reduce_action(state, actor, command, *, now)。先检查请求格式，再查 receipts；没有旧请求才检查 phase_id、expected_version、允许的工具、参数和目标。通过后 deepcopy，交给 _apply 按 tool 分支修改副本，version 加一并保存回执。函数返回 (updated, receipt)，不执行 SQL。

04 · full_game.py：阶段怎样继续？

打开 Archify 流程图 ↗

普通行动在 _apply 中更新 completed[str(actor)]；所有 actors 都完成才依次调用 _settle、_advance。_settle 统计投票，必要时把平票等任务插到 queue 前面。_advance 用最多100次的 for 循环，取 queue.pop(0)，更新阶段，再按阶段计算 actors。next_night、dawn 自动处理后 continue；没有行动者则结算并继续；有行动者便 return，等待下一次请求。

pending(state) 从 actors 中排除已完成席位，发言阶段只给下一人。它不是所有允许工具的清单；额外技能仍由 tools 判断。wolf_chat 记录后提前 return；explode 自己设置队列并推进，不走普通投票分支。

注意同名区别：full_game._advance 只改字典与列表，返回 None；web.advance 是 HTTP 路由，检查 waiting 后最多启动一个 AI 决策窗口。

真实代码节选：full_game.py:166–181；省略部分请点源码。

def _advance(state, now):
    # 空阶段自动跳过，不通过公开口播透露是否仍有对应夜间身份。
    for _ in range(100):
        if state["winner"] or not state["queue"]:
            return
        task = state["queue"].pop(0)
        phase = task["name"]
        state.update(phase=phase, phase_id=str(uuid4()), completed={}, task=task)
        seats = alive(state)
        if phase == "next_night":
            state["round"] += 1
            _night(state)
            continue
        if phase == "dawn":
            _dawn(state, now)
            continue

05 · ai.py：模型回复怎样变成输入？

打开 Archify 流程图 ↗

DecisionRunner.run(session, persona) 先读该玩家的 view。model_step 准备消息与工具描述，执行 self.model.bind_tools(...).invoke(messages) 请求模型。模型返回 tool_calls；dispatch 对每项 name/args 分支，查询调 session.query，行动则补上 request_id、phase_id、expected_version 后调 session.submit，仍由规则检查。

LoopState 保存 rounds、messages、calls、audit、done 等循环数据。只有 model_step、dispatch、fallback 三个函数被 add_node 注册；after_model / after_dispatch 是返回下一跳名称的条件函数。图把这些条件函数也展开，方便读 Python 分支，不能把图框数当作 LangGraph 节点数。

查询与 wolf_chat 可继续下一轮；其他成功行动令 done=True，剩余工具标记 window_completed。模型异常或默认3轮用尽走 fallback；窗口已变或无可用工具则结束，否则尝试规则允许的自动弃权。每轮最多处理8项工具调用。

06 · retrieval.py / semantic.py：只从可见文本里选

打开 Archify 流程图 ↗

PlayerSession.query(name, payload) 先调用 self.view，再交给 retrieval.query。历史候选由 history_documents(view) 从可见事件形成；世界书候选由 visible_entries(book, role) 筛选。之后才按需分块、评分。Chunk 是文本段及来源信息，SemanticIndex 是本次 chunks 的封装，没有持久化向量数据库。

semantic.scores(documents, query) 返回浮点数列表：_embed_many 先查 _CACHE[text]，缺失才由 ONNX CPU 模型计算向量，再做点积。retrieval 按分数排序，阈值0.40、同来源去重，最多返回12份原文档。self_info 直接返回事实，summarize_player 取摘录，空查询也不走语义模型。

实际查询“谁认为那个手艺人不太对劲”：两条公开文本分数约0.445与0.307，结果 sources 包含 event:37，method=semantic_retrieval；私密 event:14 没有进入候选。同一问题首次2批推理，第二次0批。故障注入 EmbeddingUnavailable 后走词项匹配，本例变成 event:38，method=lexical_fallback 且带 warning，不能说降级结果相同。

返回字典包含 answer、sources、method，必要时加 warning；不写游戏状态，但可能下载语义模型、更新向量缓存。Web 的 safe_query 可再经 assistant.assist 请求聊天模型整理已选来源；AI 工具查询直接返回检索结果，不走这个整理步骤。

真实代码节选：retrieval.py:182–192；省略部分请点源码。

def _rank(documents, question, *, view):
    if not question.strip():
        return documents[-RESULT_LIMIT:], "extractive_retrieval", None
    index = SemanticIndex.build(documents, view=view)
    try:
        matches = index.search(question)
    except semantic.EmbeddingUnavailable as exc:
        _LOG.warning("语义检索不可用，回退词项检索：%s", exc)
        matches = _lexical_rank(documents, question)
        return matches, "lexical_fallback", "语义模型不可用，已回退词项检索。"
    return matches, "semantic_retrieval", None
