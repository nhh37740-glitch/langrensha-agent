## 结构好在哪里，有什么证据

**现有后端有可用的模块化单体骨架，尚无依据要求推倒重写。** 这不等于所有职责已分得理想，也不等于已通过完整安全或容量审计。

- 业务裁定不依赖 HTTP、数据库和模型；`full_game.reduce_action` 返回状态，`GameService._submit` 持有事务，利于规则单测。[源码](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/service.py#L112-L129)
- AI 工具执行与真人行动共用规则入口；固定席位不来自模型参数，过期窗口和版本由内核拒绝。[源码](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/ai.py#L283-L326)
- `pyproject.toml` 的四个 Import Linter 契约覆盖全部模块分类、同层独立、纯规则禁止框架依赖、AI 禁止导入受信层以及 Store 导入者限制；[负例测试](../../../tests/test_architecture.py)故意破坏依赖确认检查会报错。这是可执行限制，不只是画了几层方框。[契约原文](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/pyproject.toml#L43-L77)
- 世界书权限过滤先于候选分块与向量排序，语义模型失败有显式回退；这两项都有已有回归测试，见下表。

## 现有结构的具体问题与建议

下列建议按实际职责和变化传播判断，不以文件行数作为质量评分；本次均未改业务代码。

| 核实到的现状 | 影响 | 建议与适用条件 |
| --- | --- | --- |
| [web.create_app](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/web.py#L23-L101) 同时装配服务、建/迁移会话表、认证；后半段还做路由和 AI 调度 | 网络层知道会话 schema，修改生命周期需要同时关注 SQL、cookie 和路由 | 下一次会话需求变化时，优先考虑抽取会话存储边界；当前无需为目录整齐而全仓搬迁 |
| [GameService.store](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/service.py#L29-L33) 可直接访问，web 经它写 SQL；PlayerSession 又持有 `_service` | “Store 只允许 service 导入”不等于只有 service 能操作数据库；封装依赖调用者遵守约定 | 将来若增加不受信的 Python 插件，应另做能力隔离；当前模型文本和受信 Python 编排要区分 |
| [调试开关默认 1](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/web.py#L28-L34)，同一已登录会话可切换并读取主持数据 | 普通视图权限成立，整个 Web 接口却并非普通玩家信息边界；生产/多人使用时影响信任假设 | 本轮只如实说明已授权开发行为；进入生产范围前单独确认默认值和调试授权，不能把关闭 UI 当作服务器权限隔离 |
| [advance_lock](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/web.py#L234-L259) 是整个 app 的单锁，推理期间一直持有；启动固定 `workers=1` | 不同局的推进也会竞争；新增 worker 不会共享该锁。现有实现有意限制部署方式 | 只有并发用户需求成立时再设计每局调度与跨进程协调；未做负载测试，不给出并发容量数字 |
| [Store.transaction](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/store.py#L27-L53) 对查看也用 `BEGIN IMMEDIATE`；每次行动序列化整局 JSON（含事件、回执） | 读路径也竞争写事务，长局账本增大后读写成本增加；不是独立事件表或事件溯源重建 | 出现量测瓶颈后再比较只读事务、快照与历史拆分，保留原子提交及幂等语义 |
| [rules.py](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/rules.py#L12-L97) 兼有基础定义与演练内核，full_game 复用其 `create_game`、`_text` 等 | 新读者容易把演练当正式规则；演练改动可能影响完整局共用部分 | 先明确阅读入口；以后确有规则扩展需求时再提独立 Issue 分离共用基础，不删历史功能 |
| [ai.tool_schemas](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/ai.py#L159-L221) 的说明和 `assistant` 系统提示仍含雾钟镇称谓；规则工具、展示标签分别维护 | 角色称谓已统一来源，但“世界化”没有覆盖全部模型文案；新增技能须协调规则、工具 schema、呈现 | 后续按真实世界书/技能需求梳理命名来源，优先解决用户可见不一致；不能误称本次已修复 |

另外，`operations.py` 通过 `sqlite3` 直接做完整性检查、一致性备份及恢复到新路径；这是运维入口，[证据](https://github.com/nhh37740-glitch/langrensha-agent/blob/182133f294a5eed10460b097f9f5e6e5a8ffb9e9/src/langrensha/operations.py#L97-L180)。因此“Store 是整个仓库唯一数据库访问者”同样不成立。主结构图聚焦游戏请求，未将运维画入请求链。

## 验证对应什么结论

| 验证 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| `lint-imports` 与 `tests/test_architecture.py` | 当前静态依赖满足契约，指定违规会被拒绝 | Python 运行时沙箱、动态导入安全 |
| `test_full_game.py`、`test_kernel.py` | 已有规则、视图、幂等与并发条件的回归 | 穷尽全部规则组合 |
| `test_ai.py`、`test_assistant.py` | 工具分流、身份不可伪造、错误回退、札记引用检查 | 真实模型在每局都做出正确策略 |
| `test_retrieval_web.py`、`test_semantic_retrieval.py`、`test_debug_mode.py` | 普通权限与调试例外、查询/向量路径的已有回归 | 任意恶意插件隔离或生产渗透审计 |
| Archify 源码证据、重建、严格校验、浏览器布局检查 | 图源、HTML、凭据与引用提交一致；自动布局检查通过时可复现 | 真实新读者已经看懂 |

本地 Chrome 在加载图时返回 `net::ERR_BLOCKED_BY_ADMINISTRATOR`，没有修改或绕过环境策略；本地通过的图验证仅包括源码/结构、交付与严格产物校验，真实浏览器门由现有“版本图检查”在 GitHub Actions 运行。最终结果以本 Issue 对应 PR 当前 head 的五项 CI 和 Codex review 记录为准；不能用提交审查请求代替完成审查。未调用真实 DeepSeek、未部署、未发布版本。
