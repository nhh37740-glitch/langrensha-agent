# 架构与设计模式评估

日期：2026-10-23（北京时间）。状态：**用户已确认 Python 模块化单体，并已指示按此前架构方向进入详细设计**；其他设计模式仍是建议，具体设计可依据需求与裁定修订。依据：[已确认的需求基线](../需求/需求分析.md)。本稿只决定架构方向与设计模式的取舍，不划分业务模块、接口、数据表或文件结构。

## 结论与理由

用户于 2026-10-23 确认：首版整体采用 **Python 模块化单体**。各业务职责在同一后端项目内保持清楚边界；这项决定不等于确认下面所有内部设计模式。

建议采用**有状态对局流程 + 受控工具调用的角色代理**：由 LangGraph 管理一局游戏的阶段、轮次、暂停恢复和状态转换；由 LangChain 提供模型与工具调用能力，让人工智能玩家在轮到自己时决定发言或提出合法行动。游戏规则负责判定行动是否有效及何时结束，模型负责推理和选择。LangGraph 官方说明其适合把确定性步骤与模型驱动步骤放在同一流程中；LangChain 官方工具说明支持模型直接产生带参数的工具调用。[LangGraph 概览](https://docs.langchain.com/oss/python/langgraph/overview) · [LangChain 工具](https://docs.langchain.com/oss/python/langchain/tools)

| 候选模式 | 对本项目的适配 | 结论 |
| --- | --- | --- |
| 单个模型持续对话，以文本或 JSON 指令推进游戏 | 容易起步，但昼夜流程、合法行动、断点恢复及隐私边界依赖额外的解析与约束，难以证明角色工具确实被调用。 | 不作为主架构。 |
| 仅用通用工具调用代理反复运行 | 能实现模型调用工具，适合角色内部的短时决策；完整对局的轮次、胜负与真人等待仍需明确编排。 | 用于角色决策，不单独承载全局对局。 |
| LangGraph 管理对局，LangChain 支持角色工具调用 | 可显式记录阶段并等待真人输入，把规则确定性与角色自主决策结合；复杂度比简单聊天代理更高。 | 推荐作为首个版本的架构方向。 |

对局推进采用明确的状态转换。用户先提出“每次行动循环是一个新代理”，后又指出反复创建可能拖慢对局；本稿据此区分**运行组件复用**与**决策上下文隔离**：模型连接、无状态执行组件及相同工具配置可以复用；每次轮到 AI 时仍须重新读取该玩家当前可见记录，确定本阶段工具权限，不沿用其他玩家或旧阶段的私有会话记忆。是否复用具体代理对象取决于它能否可靠刷新工具和上下文，不能为了复用而给代理全部角色工具。循环中由模型原生工具调用执行行动，不解析模型写出的伪指令。用户于 2026-10-23 明确：Agent 每次行动的思考轮数由配置控制；轮数用尽仍未行动，按同阶段真人弃权规则处理，不设计用时计时。LangChain 官方将代理描述为模型与工具的循环，LangGraph 提供可控的编排与持久化能力。[LangChain 代理](https://docs.langchain.com/oss/python/langchain/agents) · [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)

## 必须守住的边界

- **规则和行动**：模型提出发言、投票或技能行动；只有当前阶段允许且符合角色身份的工具才能执行。主持与结算依据游戏规则及实际状态，不以模型口头宣称为准。这样才能复现完整对局，并核查越权调用。
- **游戏身份与虚拟人格**：游戏身份决定阵营、技能、可见资料和胜负；虚拟人格决定背景、性格及表达。角色技能资料可以按身份与场景提供给代理，但资料本身不授予额外权限。两者的组合方式留到详细设计。
- **私人信息**：完整对局状态与某位玩家可见的信息必须区分。人工智能调用模型之前，只提供该玩家有权看到的事实；工具执行时再次核对身份、阶段与权限。狼人私聊仅对狼人和主持人开放，不能靠提示词要求模型“自行保密”。
- **检索与玩家辅助**：真人和 AI 都能调用世界背景、历史发言的检索工具；先按调用者的身份和可见范围筛选，再检索与总结。真人还能获得发言建议。检索结果应能追溯到对应发言或背景资料；狼队私聊对狼人可检索，对其他玩家不可检索。具体检索技术与存储产品留到后续设计。
- **对局连续性与验收**：对局需要保存当前阶段和已生效行动，以支持真人等待、故障恢复和完整对局验收；保留工具调用与规则裁定记录，供核验角色工具实际使用。玩家能看到多少调用记录仍待需求澄清。[LangGraph 持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence)。

## 已明确的实现语言与前端工具建议

用户于 2026-10-23 明确：**后端用 Python，前端用 HTML**。前端交互可用 CSS 与 JavaScript；后端的 LangChain、LangGraph 资料按 Python 版本参考。每个世界书对应不同的网页背景和场景动画；虚拟角色的表现动画与游戏身份的技能动画分别变化。视觉表现须与本局世界、人物和已生效的技能结果对应，但不能决定技能是否生效，也不能泄露当前玩家无权看到的信息。具体素材和动画效果留待相应设计与制作阶段确定。

**用户于 2026-10-23 确认使用 [Phaser](https://docs.phaser.io/)** 实现场景、角色立绘、昼夜切换、卡牌与投票动效；它提供 [Scene](https://docs.phaser.io/phaser/concepts/scenes) 和 [Tween 动画](https://docs.phaser.io/phaser/concepts/tweens)。长对白、历史记录、选项与辅助查询界面仍用 HTML/CSS，便于阅读和操作；Phaser 可在画布上方使用 [DOM 元素](https://docs.phaser.io/phaser/concepts/gameobjects/dom-element)。具体视觉稿和动画验收仍由详细设计确定。
