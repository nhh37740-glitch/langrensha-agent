# 代码架构管理方案

对应 #23；决定日期：2026-10-24（北京时间）。用户授权 Codex 自主比较、选择并落地，保持所有游戏规则和用户功能。源码对象为完整单体，已按 #20 追踪调用，非根据模块名推断。

## 方案比较与决定

| 候选 | 对本项目的收益 | 代价与决定 |
| --- | --- | --- |
| 模块化单体 + 显式分层 + 架构适应性检查 | 保留纯 reducer、单事务及可复现构建；小步阻止依赖倒置 | **采用**。现有约 15 个 Python 模块已大体分离，无需迁移目录来获得可执行约束 |
| 完整 Clean/Hexagonal Architecture 与逐层 DTO/端口重写 | 多供应商或多存储实现时隔离替换 | 目前只有 SQLite 与一个官方模型适配器；立即增加大量接口/映射不能证明减少风险。保留会话鸭子接口，未来真实第二适配器出现再引入必要端口 |
| 全面战术 DDD/CQRS、拆聚合和领域事件总线 | 更大团队/多个业务上下文可独立演进 | 当前核心是单局确定性状态机，快照与回执须同事务。现有只读检索继续分离，暂不增加异步总线与双写一致性负担 |
| 微服务或分布式 Agent 服务 | 独立伸缩/部署 | 与当前单 worker、一局事务边界不匹配；额外认证、跨服务消息和事务成本无实际需求依据 |

架构管理采用持续检查实际依赖的成熟方法，而非一次重画目录。Import Linter 已支持层级、禁用依赖、保护模块、间接依赖与穷尽层分类；比自建 AST import 扫描器少维护一套解析/闭包实现。选用 2.15（BSD-2-Clause，Python >=3.10，当前项目 Python 3.12 满足），只作为 dev 工具，不进入 `[ai,web]` 生产依赖。五个新增开发工具/传递包版本进入约束文件，现有依赖版本保持不动。

调研来源：

- [Import Linter 官方源码与文档](https://github.com/seddonym/import-linter)：核对 forbidden、layers、protected 与 exhaustive 的实际定义。
- [Layers 官方说明](https://github.com/seddonym/import-linter/blob/main/docs/contract_types/layers.md)、[Forbidden](https://github.com/seddonym/import-linter/blob/main/docs/contract_types/forbidden.md)、[Protected](https://github.com/seddonym/import-linter/blob/main/docs/contract_types/protected.md)。
- [PyPI 2.15 包元数据](https://pypi.org/project/import-linter/2.15/)：核对版本、Python 及许可证；Read the Docs 本环境返回 403，使用官方仓库同源文档完成调查。
- [Martin Fowler：Monolith First](https://martinfowler.com/bliki/MonolithFirst.html) 为方案背景参考；本次选择主要基于本项目已核验的事务、模块和部署现状，不假称完成新分布式架构验证。

## 已落实的契约

`pyproject.toml` 为唯一可执行依赖规则，开发规范和本文解释其意义，不重复维护另一份允许表。

1. 自上而下为装配入口、应用/模型/呈现、规则执行/检索/存储、基础规则/内容。同层 `|` 表示相互独立，入口 `:` 允许互相装配。`exhaustive=true` 要求新 Python 模块明确归属，不可悄悄落入未检查空隙。
2. 纯规则、内容、检索和呈现禁止依赖 FastAPI、Uvicorn、LangChain/DeepSeek、LangGraph、LangSmith，包括经其他模块形成的间接依赖。
3. AI/札记编排禁止依赖 GameService、Store、HTTP 和运维模块，使用受限会话传入的能力；这约束静态依赖，不能替代运行时身份/工具校验。
4. Store 的直接导入只允许 GameService。Web 当前的会话 SQL 仍经 `service.store.transaction()` 执行，未假称它已经成为独立 Repository。
5. Phaser 渲染器不直接 fetch/XHR/WebSocket，也不反向导入页面入口，由页面提供已经过滤的状态。ESLint 检查这一职责边界。

## 开发和验收

```bash
python -m pip install -c requirements-dev.lock -e '.[dev,ai,web]'
lint-imports --no-cache --cache-dir 临时/架构检查/缓存
python -m pytest
npm run lint --prefix 前端
```

Actions 在原 Python 检查中强制运行 Import Linter，不增加发布门禁遗漏的新 job。四项负例复制最小源码，分别故意加入规则 → 服务、AI → Store、内容 → FastAPI 和未分类新模块，调用真实工具确认拒绝；不会修改原源码。原功能测试继续证明规则和 API 行为，不能以“依赖图通过”代替功能或权限测试。

新增模块：先写 Issue/设计，明确职责，再更新层分类和测试；禁止为消除报错添加无理由的 ignore。调整契约时附真实理由及负例验证，源码架构图同步检查。

## 保留的边界与遗留

- `service.py` 同时含 PlayerSession 和主持服务，数据库调用集中但尚未形成多个可替换 Repository；当前没有第二存储需求，未为了选型表制造接口。
- `web.py` 仍是组合根，含会话表 SQL 和逐窗口调度；如果会话生命周期/并发部署需求变复杂，再抽独立会话适配器与调度边界。
- Import Linter 检查 Python 静态依赖，不证明动态 import、反射、文件 I/O 或传入对象的能力安全。运行时受限视图、模型工具授权、数据库事务和既有权限回归继续承担这些保证。
- 本次不搬文件、不改变公开 API、游戏裁定、对局数据 schema 或持久卷；正式服务器上线仍由 #14 跟踪。
